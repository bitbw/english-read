# 每日阅读游客访问方案

## 1. 目标

允许未登录用户从落地页直接进入“每日阅读”，降低首次使用门槛；个人书架、词汇、复习、统计等功能继续要求登录。

本方案只开放每日文章，不开放图书馆和个人书籍的游客访问。

## 2. 目标用户流程

未登录用户访问网站后的目标流程：

```text
访问 /
  ↓
点击“立即体验”
  ↓
直接进入 /articles
  ↓
浏览每日文章列表
  ↓
打开文章并阅读
```

游客不需要先注册或登录，也不需要创建匿名数据库用户。

## 3. 游客页面表现

### 3.1 落地页 `/`

未登录用户打开网站首页时，仍然看到现有产品落地页，包括产品介绍、功能展示和每日英语介绍。

需要调整首页主按钮：

- “立即体验”或“免费开始”直接链接到 `/articles`。
- 不再将该按钮链接到 `/login`。
- 顶部栏的“登录”按钮继续链接到 `/login`。
- 其他宣传内容和 App 下载入口保持不变。

首页核心入口应形成以下关系：

```text
立即体验 → /articles
登录 → /login
```

### 3.2 每日阅读列表页 `/articles`

游客进入后显示每日文章列表，默认使用 L1 初级难度。

页面支持：

- 查看文章列表。
- 切换 L1、L2、L3 难度。
- 翻页。
- 打开文章详情。

如果登录用户访问 `/articles`，没有指定 URL 等级时，仍然使用用户的 `articleLevel`；如果 URL 中明确传入 `level`，则 URL 参数优先。

### 3.3 文章详情页 `/articles/[id]`

游客可以直接打开文章正文，继续使用现有阅读组件。

游客可以使用：

- 阅读正文。
- 查词、翻译和发音等不依赖用户身份的功能。
- 调整字号、主题等浏览器端阅读设置。

文章不存在时继续返回 404。

## 4. 游客菜单和顶部栏

### 4.1 桌面端左侧菜单

游客进入每日阅读后，左侧菜单只显示游客可用入口：

```text
English Read

每日英文

登录 / 注册
```

“首页”“公共书库”“我的书架”“生词本”“排行榜”“设置”等登录后功能不在游客菜单中显示，避免用户点击后才发现需要登录。

如果项目希望保留这些菜单，也必须统一跳转登录页；第一版推荐直接隐藏。

### 4.2 桌面端顶部栏

游客顶部栏建议显示：

```text
左侧：English Read 或页面返回入口
右侧：主题切换、登录 / 注册
```

游客状态下不显示：

- 用户头像。
- 用户名和账号信息。
- 退出登录。
- 个人设置入口。

### 4.3 移动端顶部栏

游客移动端顶部栏建议显示：

```text
[菜单]                              [主题] [登录]
```

点击菜单后只显示：

```text
每日英文
登录 / 注册
```

当前 `(app)/layout.tsx` 中底部导航处于注释状态，因此第一版不需要新增游客底部导航。

## 5. 游客允许和禁止的能力

### 游客允许的能力

- 查看每日文章列表。
- 按 L1、L2、L3 难度筛选文章。
- 打开文章详情并阅读正文。
- 使用现有的查词、翻译、发音等不依赖用户身份的功能。
- 在浏览器端调整阅读界面设置。

### 游客不允许的能力

- 保存服务端阅读进度。
- 累计阅读时长和学习统计。
- 添加或修改生词。
- 使用复习计划和复习记录。
- 使用个性化文章等级设置。
- 访问个人书架、图书上传和其他登录后页面。

## 6. 代码改动范围

### 6.1 放开页面路由

从 `middleware.ts` 的 `protectedRoutes` 中移除 `/articles`。

保留以下路径的登录保护：

- `/dashboard`
- `/guide`
- `/library`
- `/read`
- `/vocabulary`
- `/settings`
- `/leaderboard`
- `/admin`
- `/textreader`

### 6.2 修改落地页入口

文件：`src/app/page.tsx`

将落地页的“立即体验”或“免费开始”按钮链接改为：

```text
/articles
```

登录按钮仍然链接到：

```text
/login
```

登录用户访问 `/` 时，现有逻辑仍可继续重定向到 `/dashboard`。

### 6.3 修改文章列表页

文件：`src/app/(app)/articles/page.tsx`

移除强制登录跳转，改为使用可选会话：

- 登录用户：没有指定 URL 等级时，继续使用用户的 `articleLevel`。
- 游客：没有指定 URL 等级时，默认使用 `level = 1`。
- 如果 URL 中明确传入 `level`，游客和登录用户都按 URL 参数筛选。

不需要新增数据库字段，也不需要创建游客用户。

### 6.4 修改文章详情页

文件：`src/app/(app)/articles/[id]/page.tsx`

移除未登录时跳转 `/login` 的逻辑，直接根据文章 ID 查询 `daily_articles` 并渲染现有阅读组件。

### 6.5 修改文章读取 API

文件：

- `src/app/api/articles/route.ts`
- `src/app/api/articles/[id]/route.ts`

仅对 GET 读取接口移除 `requireSessionApi()`。

当前接口只提供 GET，因此不需要新增游客写接口。

如果后续增加文章收藏、学习记录等接口，这些接口必须继续要求登录。

### 6.6 修改游客菜单和顶部栏

文件：

- `src/app/(app)/layout.tsx`
- `src/components/layout/sidebar.tsx`
- `src/components/layout/topbar.tsx`

根据 `useSession()` 的登录状态区分游客和登录用户：

- 游客只显示“每日英文”和“登录 / 注册”。
- 登录用户保持现有完整菜单和账号菜单。
- 游客顶部栏显示登录入口，不显示头像和退出登录。
- 游客菜单中的受保护页面不应显示为可用入口。

优先复用现有 Sidebar、Topbar 和 `(app)` 布局，不新建游客专用布局。

## 7. 阅读器中的登录提示

游客打开文章后，阅读正文可以正常工作。

当游客触发以下操作时，提示登录：

- 添加生词。
- 保存阅读进度。
- 记录阅读时长。
- 查看或提交复习内容。

提示文案建议：

> 登录后即可保存生词、阅读进度和学习记录。

登录入口可以跳转到 `/login?callbackUrl=/articles/<articleId>`，登录完成后返回当前文章。

第一版不建议实现游客服务端进度同步，也不建议创建匿名数据库用户。

## 8. 权限边界

游客模式只读公开文章数据，不能通过文章接口访问用户数据。

必须保持登录保护的接口包括：

- `/api/vocabulary/*`
- `/api/review/*`
- `/api/reading/time`
- `/api/stats/*`
- `/api/books/*`
- `/api/library/*`
- `/api/user/*`
- `/api/upload/*`

文章接口只返回 `daily_articles` 的公开字段，不增加用户信息、内部管理字段或其他关联数据。

## 9. 验证清单

### 未登录状态

- 访问 `/` 可以看到落地页。
- 点击“立即体验”或“免费开始”直接进入 `/articles`，不跳转登录页。
- 访问 `/articles` 可以打开文章列表。
- 访问 `/articles?level=2` 可以查看 L2 文章。
- 访问 `/articles/<id>` 可以打开文章正文。
- 游客默认查看 L1 文章。
- 游客菜单只显示每日英文和登录 / 注册入口。
- 游客顶部栏不显示头像、账号信息和退出登录。
- 访问 `/api/articles` 返回 200。
- 访问 `/api/articles/<id>` 返回 200。
- 添加生词、保存进度等操作会提示登录或返回未授权。
- 访问 `/dashboard`、`/library`、`/vocabulary` 等页面仍跳转 `/login`。

### 登录状态

- 登录用户访问 `/` 后仍可按现有逻辑进入 `/dashboard`。
- `/articles` 默认仍使用用户的 `articleLevel`。
- URL 中指定的 `level` 仍然优先。
- 登录用户仍看到完整菜单和账号菜单。
- 文章列表和详情页行为与改动前一致。
- 生词、进度、阅读时长和统计功能不受影响。

### 建议执行的验证命令

```bash
npm run lint
npx tsc --noEmit
npm run build
```

## 10. 后续可选扩展

如果后续需要提升游客体验，可以在浏览器端使用 `localStorage` 保存临时阅读位置、字号和主题设置；登录后再将阅读位置迁移到正式用户数据。

这不是第一版必需功能，只有确认游客阅读量和登录转化率较高后再增加。
