# 复习状态与基础加练实现方案

## 1. 需求理解

单词不再只用“复习阶段”表示，而是增加用户可以主动维护的三种状态：

1. **忘记 / 完全生词**：从基础复习第 0 阶段开始。
2. **记住**：跳过剩余基础复习，进入加练阶段，从 60 天开始。
3. **掌握**：用户确认已经完全掌握，之后不再安排复习。

复习页面、单词列表都提供状态维护操作；阅读时的划词弹窗对已经存在的单词至少提供“忘记”操作，方便用户在语境中发现自己已经不熟时立即重置。

选择题答错不直接改变状态。因为当前干扰项仍可能出现同义或近义选项，预计约 20% 的额外错误属于题目误导，不能把它们全部当作真正遗忘。

## 2. 为何采用“基础复习 + 加练 + 掌握”

基础复习用于让新词形成初步记忆：

`1 → 2 → 4 → 7 → 15 → 30 天`

加练用于已经基本记住、但还没有完全掌握的词：

`60 → 120 → 240 天`

掌握不是加练的下一个自动阶段，而是用户主动确认后的终态。这样可以避免系统仅凭几次答题就替用户宣布“永久掌握”。

## 3. 状态与阶段模型

### 3.1 复用现有字段，不新增状态字段

当前 `vocabulary` 已有：

- `reviewStage`
- `nextReviewAt`
- `isMastered`
- `masteredAt`

优先复用现有字段，通过阶段范围和 `isMastered` 组合出三种状态，不新增数据库字段：

| 用户状态 | `isMastered` | `reviewStage` | 复习计划 |
|---|---:|---:|---|
| 忘记 / 完全生词 | `false` | `0～5` | 基础复习 1～30 天 |
| 记住 | `false` | `6～8` | 加练 60、120、240 天 |
| 掌握 | `true` | 保留当前值 | 不再复习 |

阶段含义：

- `0`：基础复习起点，下一次为 1 天后；
- `1`：下一次为 2 天后；
- `2`：下一次为 4 天后；
- `3`：下一次为 7 天后；
- `4`：下一次为 15 天后；
- `5`：下一次为 30 天后；
- `6`：加练第 1 次，下一次为 60 天后；
- `7`：加练第 2 次，下一次为 120 天后；
- `8`：加练第 3 次，下一次为 240 天后；
- `isMastered = true`：掌握，不再复习。

现有已经 `isMastered = true` 的数据继续视为“掌握”，不需要迁移。新逻辑只需要把未掌握词的阶段 6～8 解释为“记住 / 加练中”。

### 3.2 状态展示

不要再只根据 `reviewStage` 显示“已掌握”：

- `isMastered = true`：显示“掌握”；
- `isMastered = false && reviewStage >= 6`：显示“记住 / 加练中”；
- `isMastered = false && reviewStage < 6`：显示“忘记 / 基础复习中”。

建议在 `src/lib/srs.ts` 集中提供状态判断和阶段名称，列表、复习页、划词弹窗统一复用，避免各页面自行判断。

## 4. 状态流转

### 4.1 基础复习中的单词

默认保持现有基础复习节奏：

`0 → 1 → 2 → 3 → 4 → 5`

每次正常完成复习后，按基础间隔进入下一阶段。

用户可以主动操作：

- 点击“记住了”：直接跳到加练阶段 6，安排 60 天后复习；
- 点击“忘记了”：回到阶段 0，安排 1 天后复习；
- 不提供“掌握了”或禁用该按钮，因为用户尚未进入加练阶段。

这里保留基础阶段的意义：默认复习仍然按 1、2、4、7、15、30 天逐步推进；“记住了”是给熟词用户使用的提前跳级操作，而不是把每次答题正确都自动跳到 60 天。

### 4.2 加练中的单词

加练阶段按以下顺序推进：

`6 → 7 → 8`

用户可以主动操作：

- 点击“记住了”：进入下一个加练阶段，间隔为 60、120、240 天；
- 点击“忘记了”：回到基础阶段 0，安排 1 天后复习；
- 点击“掌握了”：设置 `isMastered = true`，清除后续复习入口。

“掌握了”只在 `reviewStage >= 6 && isMastered = false` 时可用。

### 4.3 已掌握的单词

掌握状态不进入复习队列，用户仍可以主动维护：

- 单词列表点击“忘记了”：回到基础阶段 0；
- 划词弹窗点击“忘记了”：回到基础阶段 0；
- 单词列表点击“记住了”：进入加练阶段 6；
- “掌握了”按钮保持禁用或不显示。

这样用户遇到某个已经掌握、但实际阅读时反应不出来的词，可以立即重新纳入基础复习。

## 5. 复习页面交互

### 5.1 答题与状态操作分离

当前释义选择和拼写练习继续保留，但答题结果不直接决定用户状态：

1. 用户完成当前单词的释义和拼写练习；
2. 页面展示当前状态和下一步复习间隔；
3. 用户选择“记住了”或“忘记了”；
4. 加练阶段额外展示“掌握了”；
5. 只有状态按钮提交后，才更新 `vocabulary` 和 `review_logs`。

题目答错只用于：

- 当前轮次将单词重新排到后面；
- 记录普通答题错误统计；
- 必要时增加一次有限的额外练习。

题目答错不直接调用“忘记”状态接口。

### 5.2 按当前状态显示按钮

| 当前状态 | 显示按钮 | 结果 |
|---|---|---|
| 忘记 / 基础复习中 | 继续基础复习、记住了、忘记了 | 按基础间隔推进，或进入加练 60 天，或重置基础 0 |
| 记住 / 加练中 | 继续加练、忘记了、掌握了 | 进入下一个加练阶段，或重置基础 0，或永久停止 |
| 掌握 | 复习页默认不出现 | 通过列表或划词弹窗手动重新加入复习 |

按钮文案建议明确表达长期影响：

- `记住了：进入加练，60 天后再见`；
- `忘记了：从基础复习重新开始`；
- `掌握了：以后不再安排复习`。

## 6. 单词列表操作

### 6.1 每个词的可用操作

单词列表的卡片视图和表格视图都支持状态操作：

- 忘记了；
- 记住了；
- 掌握了。

操作规则与复习页一致：

- “掌握了”只有记住 / 加练状态可用；
- 对基础复习词点击“记住了”，直接进入阶段 6；
- 对掌握词点击“忘记了”，回到阶段 0；
- 每次手动修改后刷新当前行和待复习数量，不需要刷新整个页面。

### 6.2 操作确认

“忘记了”和“掌握了”都会改变长期排期，建议保留轻量确认：

- 第一次点击直接执行并显示 Toast；
- 仅“掌握了”使用确认弹窗，避免误点后永久移出复习队列；
- 提供撤销或立即显示“改为记住 / 忘记”操作，减少误操作成本。

## 7. 划词弹窗操作

阅读时选中的单词如果已经存在于生词本，弹窗增加“忘记了”操作：

- 将单词设置为基础阶段 0；
- 下一次复习安排为 1 天后；
- 保留原有释义、原句、来源书籍和复习记录；
- 不删除并重新创建单词，避免重复词和丢失上下文。

划词弹窗本次只增加“忘记了”即可。列表已经提供完整状态维护，弹窗不重复做复杂操作。

## 8. 接口与核心逻辑改动

### 8.1 统一状态动作

现有 `/api/review/submit` 只支持 `remembered` 和 `forgotten`，需要扩展为明确动作：

- `remembered`：按当前状态进入下一个基础或加练阶段；
- `promote`：跳过基础复习，进入加练阶段 6；
- `forgotten`：回到基础阶段 0；
- `mastered`：仅允许加练阶段执行，设置 `isMastered = true`。

如果不想扩展现有复习接口，可以新增一个复用逻辑的状态接口，例如：

`POST /api/vocabulary/:id/status`

请求体：

```json
{
  "status": "forgotten | remembered | mastered"
}
```

推荐将状态转换函数放在 `src/lib/srs.ts`，复习页、单词列表、划词弹窗都调用同一套后端逻辑。

### 8.2 建议的核心转换

| 动作 | `reviewStage` | `nextReviewAt` | `isMastered` |
|---|---:|---|---:|
| 忘记了 | `0` | 明天 0 点 | `false` |
| 基础阶段记住了 | `6` | 60 天后 | `false` |
| 加练 6 记住了 | `7` | 120 天后 | `false` |
| 加练 7 记住了 | `8` | 240 天后 | `false` |
| 加练 8 记住了 | `8` | 继续维护或按产品决定 | `false` |
| 加练阶段掌握了 | 保留 `6～8` | 保留或更新为当前时间 | `true` |

阶段 8 复习答对后，如果用户没有点击“掌握了”，继续保持阶段 8 并安排下一次较长维护复习。推荐先使用 240 天循环，不再新增更多阶段。

### 8.3 查询条件

基础复习和加练都属于 `isMastered = false`，因此现有复习查询大部分可以保留：

- `isMastered = false` 的词按 `nextReviewAt` 进入队列；
- `isMastered = true` 的词不进入正常复习；
- 已掌握词只有用户从列表或划词弹窗主动改为“忘记 / 记住”后，才重新进入队列。

这比让掌握词每隔一年自动出现更符合“掌握就是完全不需要复习”的定义。

## 9. 复习记录与统计

`review_logs` 继续记录真正改变状态的动作：

- 基础阶段正常推进；
- 进入加练；
- 忘记并重置；
- 掌握并停止复习。

普通题目答错建议单独记录为答题错误统计，不写成 `forgotten`。这样可以分别观察：

- 题目是否有歧义；
- 用户是否主动确认忘记；
- 哪些单词真正需要重新进入基础复习。

## 10. 实现顺序

1. 修改 `src/lib/srs.ts`，定义基础阶段、加练阶段和三种状态转换。
2. 修改复习提交接口，支持“记住、忘记、掌握”动作并校验状态流转。
3. 修改复习页面，在答题完成后展示状态操作按钮。
4. 修改单词卡片和表格，增加状态操作菜单。
5. 修改划词弹窗，仅增加已存在单词的“忘记了”操作。
6. 修改中文和英文翻译文案。
7. 补充状态转换单元测试和接口权限测试。
8. 使用 Playwright 验证复习页、单词列表、划词弹窗的关键交互。

## 11. 验收标准

- 新词从基础阶段 0 开始，默认按照 1、2、4、7、15、30 天推进。
- 基础复习中的单词点击“记住了”后，直接进入加练阶段 6，安排 60 天后复习。
- 加练阶段可以点击“记住了”进入下一个加练间隔。
- 只有加练阶段可以点击“掌握了”。
- 点击“掌握了”后，单词不再出现在复习队列和复习计划中。
- 任意可维护状态点击“忘记了”后，都回到基础阶段 0，安排 1 天后复习。
- 选择题答错不会直接导致阶段降级。
- 单词列表可以完成忘记、记住、掌握操作。
- 已存在单词的划词弹窗可以直接执行“忘记了”。
- 所有入口使用同一个状态转换逻辑，不出现页面之间规则不一致。

## 12. 本次明确不做

- 不因为一次选择题答错就自动进入“忘记”；
- 不把“记住了”解释为永久掌握；
- 不让掌握状态自动按 60、120、240 天复习；
- 不新增复杂的 FSRS / SM-2 算法；
- 不新增数据库状态字段，除非后续数据证明现有字段无法表达需求。
